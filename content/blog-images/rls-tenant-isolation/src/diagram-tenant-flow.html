Row-level security

How one request gets scoped to one tenant

1
API request
Authenticates with an API key.
2
Middleware
Resolves the key to a tenant and puts the tenant ID into the request context.
3
Transaction sets the tenant app_role
Tenant ID goes in as a bound value, local to this transaction only.
BEGIN; SELECT set_config('app.tenant_id', $1, true);
4
RLS policy filters every query
PostgreSQL adds the policy condition to the query.
SELECT * FROM orders; -- policy: USING (tenant_id = -- current_setting('app.tenant_id', true)::uuid)
tenant Areturned
tenant Bfiltered out
tenant Areturned

Commit or rollback
The setting resets, so it can't leak to the next request on a pooled connection.
No tenant set?
current_setting(…, true) returns NULL. No rows match, so it fails closed.
